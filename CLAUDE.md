# Escape the Ramps — BACKEND (game server)

Frontend (3D client) lives at `../Escape-the-ramps`. Colyseus + Mongo, ported from `C:\ThreeJS\Kayak-and-surf\Kayak-and-surf -backend`.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- The client keeps NO progress in the browser: this server's Mongo doc is the player's only save. A guest's (or a serverless session's) progress lasts the page only.
- Messages client -> server: `saveProgress` (the whole snapshot from the client's `game.snapshot()`, sent after each local save), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session), `giftPart` (`{ to: sessionId, part }`: the sender's client already paid gems; relayed only if `part` matches `ID_PATTERN`, at most one per `GIFT_EVERY_MS` per sender, else dropped silently). Server -> client (private): `progress` (the saved doc, sanitized), `noProgress` (new account, guest, or no database: the client keeps its local state and pushes it), `serverError` (the save could not be read: saving stays off), `leaderboard`, `gift` { part, from: sender's username || "Player" } (to the target only), `giftFailed` { part } (to the sender when the target is themself or not in this room: the client refunds). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp`.
- Saved progress shape (`PlayerDoc`, client `src/game.js` `SAVED_KEYS`): `wins`, `gears`, `gems`, `speed`, `level`, `xp`, `rebirths`, `bestStage`, `owned[]`/`car` (equipped must be owned), `magnet`, `chestDay`, `parts`/`equipped` ({ id: n }, equipped <= owned), `tuneSlots`, `tuneShop` { period, sold }, `daily` { next, last }, `winsBoostUntil`, `vip` (permanent pass), `balloonsUntil`/`wingsUntil` (epoch ms, clamped like `winsBoostUntil`), `nitroBank`, `runs` { stage: { best, medal, falls, clears } }, `playtime` (`$max`, never drops), `lastSeen`. Derived values (speedMulti, tuning %) are recomputed by the client.
- Leaderboards (`src/leaderboard.ts`, `test/Leaderboard.test.ts`): the hub's three boards (client `hub/west.js`). Top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`wins`, `speed`, `playtime`), read with find/sort/limit into one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; each player's own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS`. `connectDb` creates a descending index per stat.
- `src/constants.ts` bounds must cover the client's `src/config.js` (catalog ids match `ID_PATTERN`, incl. engine `ladder-N`; currency up to ~3.6e28). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100 for party play; no `seatCap`: the matchmaker sizes pods). Needs repo var/secret `LEGION_GAME_ID` override (defaults to `escape-the-ramps`) and secret `LEGION_DEPLOY_TOKEN`.
